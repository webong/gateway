# Keep desired-state resources shared, and operational records purpose-built

Planner is a CMS for operator-managed desired state, so Email domains, aliases, mailbox connections, suppressions, schedules, and workload definitions should be represented as typed Planner Resources in the shared encrypted, versioned collection rather than each requiring a configuration table. Traffic and execution produce different data: events, deliveries, schedule runs, idempotency receipts, leases, and usage counters need atomic claims, indexed queries, retention, and sometimes foreign keys. Those remain operational records in purpose-built or reusable operational tables; forcing them into encrypted resource documents would weaken concurrency and query guarantees. Kind-specific modules own validation and projection, while the shared resource store owns identity, revision, and audit history.
