# Supported extensions for Gateway v0.2.0-rc.1

This preview supports Gateway as its own service on Linux amd64 and arm64.
RoadRunner is the default Router; FrankenPHP is the alternative. The exact release
source and manifest digest are recorded in `v0.2.0-rc.1.freeze.json`.

| Component / extension | Selected version | Preview support |
| --- | --- | --- |
| Gateway Router | 0.2.0-rc.1 | Standalone HTTP ingress/delivery, management API/CLI, SQLite/local spool, same-version replacement and stopped-volume restore. Both runtimes on both architectures. |
| Web (`webong/web`) | 0.2.0-rc.1 | Installable Web runtime for WebSocket and Webstream (SSE) traffic. The matching PHP policy package is included in Router; no separate Composer installation is required. |
| Custom extension packages | Independently versioned | Compatible `ext.package/v1` / `ext.plugin/v1` packages using the capabilities their selected host advertises. The packaged companion activation/integrity fixture passed; this does not certify arbitrary third-party extensions. |
| DNS (`webong/dns`) | Not selected | Outside the supported preview artifact set. |
| Email (`webong/email`) | Not selected | Outside the supported preview artifact set. |
| JavaScript, Lua, Shell, Go, PHP and HookScript runtimes | Not selected | Outside the supported preview artifact set. HookScript's test fixture version is not a released support promise. |
| Reverb, Mercure and Centrifugo provisioning | Not selected | Managed HTTP/WebSocket proxying is tested separately; controller recovery, fencing and deployment-specific provisioning are outside this preview. |
| Weaver (`webong/gateway-weaver`) | Not selected | Remains separately unpublished. Its workflow migration is not part of this release. |
| Database protocol extension | Not selected | No runnable database protocol gateway is shipped. |

Existing guest releases v0.1.0/v0.1.1 remain historical releases. They are not the
selected extension versions for this preview. Do not silently substitute them
for the frozen Web archives or imply that optional protocols were certified by
WWW acceptance.

Web runtime identity `webong/web` is distinct from the PHP Composer package name
`webong/gateway-web`. PHP integration code is frozen inside the Router images at
the selected source commit; no Composer split branches, tags or metadata are
published by this freeze. Existing-app Laravel/Symfony embedding is outside the
initial support scope.

## Artifact and validation boundaries

The freeze contains four loadable Docker image archives, two Web runtime
archives, a complete source archive, checksums and validation/build evidence.
Archive hashes and image configuration IDs identify the tested local bytes.
Registry manifest/index digests do not exist until a separately approved push;
they must be recorded then, never invented from local archive hashes.

Arm64 validation is native on the local machine. Amd64 validation of the frozen
bytes is emulated locally; the preceding native four-job CI run is separate
source-level acceptance, not native execution of these locally exported bytes.
Reports must retain that distinction.

Public-origin download/trust acceptance, production operation and cross-version
schema downgrade are outside this freeze. A future publication must promote the
frozen bytes without rebuilding, preserve the checksums, and verify the resulting
registry/image and extension installation from fresh caches.
